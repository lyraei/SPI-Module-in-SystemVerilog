# ALU (`exe_unit_rtl`)

Plik: `MODEL/SPI_EXE_UNIT_1/exe_unit_1_rtl.sv`, moduł `exe_unit_rtl` (1417 linii).

To **netlista wygenerowana przez Yosysa** (nagłówek `Generated by Yosys 0.12+54`), złożona z bramek `&`, `|`, `^`, `~`. W repozytorium nie ma źródeł behawioralnych. Układ jest czysto **kombinacyjny**:

| Port | Kier. | Szer. | Opis |
|---|---|---|---|
| `i_argA` | in | 8 | argument A |
| `i_argB` | in | 8 | argument B |
| `i_oper` | in | 4 | kod operacji |
| `o_result` | out | 8 | wynik |
| `o_SF`, `o_OF`, `o_NF`, `o_BF` | out | 1 | flagi |

Podmoduły netlisty: `crc_eval` (×2), `onehot2nkb_encoder`, `priority_encoder`, `sign_to_u2`, `u2tosign_module`, `zero_counter`. Po `flatten` w syntezie znikają w jednym module `spi_exe_unit_1_rtl`.

## Metoda

Netlistę zasymulowano (Icarus Verilog) dla **wszystkich 16 × 256 × 256 = 1 048 576 kombinacji** wejść i dopasowano funkcje. Każdy wiersz tabel poniżej zgadza się z netlistą w **100%** przypadków. Przypisanie podmodułu do opcode'u wynika z porównania zachowania z nazwą.

Oznaczenia:

- `A`, `B`: wejścia bez znaku 0..255, wynik zawsze modulo 256;
- `clmul(x, y)`: mnożenie bez przeniesień (wielomiany nad GF(2));
- „U2”: kod uzupełnień do dwóch, „ZM”: znak-moduł.

## Operacje

| Opcode | Operacja | Szczegóły / przypadki brzegowe |
|---|---|---|
| 0 | `A − B` | modulo 256 |
| 1 | `A XOR B` | |
| 2 | `NAND`: `~(A & B)` | |
| 3 | `A << B` | `B ≥ 8` → 0 |
| 4 | `A >> B` (logiczne) | `B ≥ 8` → 0 |
| 5 | „CRC” (`crc_eval`, `i_crc=0`) | `clmul(A[2:0], B[2:0]) & 3'b111`. Zależy tylko od 3 najmłodszych bitów A i B. **To nie jest reszta z dzielenia wielomianów**, więc implementacja CRC jest wadliwa |
| 6 | „sprawdzenie CRC” (`crc_eval`, `i_crc=B[6:4]`) | `clmul(A[2:0], B[2:0])[2:0] XOR B[6:4]`. Wynik 0 oznacza „zgodne” z op 5 |
| 7 | indeks najmłodszej jedynki A (`onehot2nkb_encoder`) | dla A one-hot to konwersja one-hot → NKB; `A=0` → 0 |
| 8 | liczba zer w `{A, B}` (`zero_counter`) | **modulo 16**: `A=B=0` daje 0 zamiast 16 (4-bitowe wyjście) |
| 9 | U2 → ZM (`u2tosign_module`) | `A ≥ 128`: `128 \| (−A)`; `A=128` → 128 („−0”, bo −128 nie mieści się w ZM) |
| 10 | ZM → U2 (`sign_to_u2`) | `A ≥ 128`: `−(A & 127)`; `A=128` („−0”) → 0 |
| 11 | indeks najstarszej jedynki A (`priority_encoder`) | `A=0` → **7** |
| 12–15 | — | wynik 0 |

## Flagi

Flagi są funkcją samego **wyniku** `R = o_result`, niezależnie od opcode'u i argumentów. Nazwy portów nie odpowiadają zachowaniu. Poniżej zachowanie zmierzone:

| Bit w odpowiedzi | Port | Zachowanie |
|---|---|---|
| F0 (`o_data[16]`) | `o_SF` | `R[7]` (znak) |
| F1 (`o_data[17]`) | `o_OF` | `R == 8'hFF` (**nie** jest to przepełnienie) |
| F2 (`o_data[18]`) | `o_NF` | parzysta liczba jedynek w R (`R=0` → 1) |
| F3 (`o_data[19]`) | `o_BF` | R ma dokładnie jedną jedynkę (one-hot) |

Dla opcode'ów „pustych” (12–15, wynik 0) flagi i tak się ustawiają: F2=1, bo zero ma parzystą liczbę jedynek. Dlatego oczekiwana odpowiedź `28'b0000_0000_0100_0000…` pojawia się w wektorach tak często.

## Przykłady

| A | B | Op | R | F3 F2 F1 F0 | Komentarz |
|---|---|---|---|---|---|
| 5 | 3 | 0 | 2 | 1 0 0 0 | 5−3=2, one-hot |
| 0 | 1 | 0 | 255 | 0 1 1 1 | 0−1=0xFF: znak, „OF”, parzysta liczba jedynek |
| 5 | 3 | 3 | 40 | 0 1 0 0 | 5<<3 = 0b00101000 |
| 200 | 0 | 11 | 7 | 0 0 0 0 | najstarsza jedynka 200 = bit 7 |

## Uwagi

- Moduły „CRC” liczą tylko obcięty iloczyn wielomianów, a nie resztę z dzielenia. Wyniki są deterministyczne i testowane, ale nie odpowiadają definicji CRC.
- Źródła behawioralne ALU należałoby dodać do repozytorium (README B6).
